# Odds Tracker

Отслеживает резкие скачки коэффициентов (в первую очередь на азиатских/шарповых
конторах — Pinnacle, 1xBet) по футболу и теннису, шлёт алерты в Telegram и
держит живой HTML-дашборд. На дашборде и в алертах есть три независимых слоя
анализа: **скачки** (резкое движение линии на одной конторе), **sharp vs
public** (кто двигается первым — умные деньги или массовый рынок), **Азия vs
Европа** (чисто географическое сравнение средних коэффициентов), и **CLV
(Closing Line Value)** — сверка, продолжила ли линия двигаться в ту же
сторону, что и наш алерт, вплоть до старта матча. CLV — стандартный
профессиональный способ судить о качестве сигнала в беттинге, он надёжнее,
чем просто win/loss по итогу матча (можно "угадать" исход на удаче, а можно
"не угадать", но точно поймать движение рынка).

## Провайдер: The Odds API

2026-07-29 проект переехал с OddsPapi на **the-odds-api.com** — у OddsPapi
бесплатный тариф оказался ограничен 250 запросами в месяц ВСЕГО, чего не
хватает даже на несколько часов поллинга. Оплачен тариф **"20K"** ($30/мес,
20 000 кредитов) — на нём доступны все конторы, включая Pinnacle и 1xBet
(доступ к конторам не зависит от тарифа, только объём кредитов).

**Важная честная оговорка по покрытию** (проверено вживую 29.07.2026 по
реальному ключу):
- **Киберспорта (CS2, LoL, Dota2) на этой API нет вообще.** Это реальное
  сокращение охвата по сравнению с первоначальным планом на OddsPapi —
  почини это можно только добавив второй, отдельный провайдер под киберспорт.
- **SBOBET, Maxbet, Singbet, bet365 не покрываются.** Из "азиатских шарпов"
  остались только **Pinnacle** и **1xBet** — Pinnacle по-прежнему самая
  важная референсная контора, так что это приемлемый компромисс за переход
  с лимита 250/мес на рабочий объём.
- Теннис не имеет одного стабильного "ATP tour" ключа — набор турниров в
  сезоне меняется (например, в июле был только Washington Open). `main.py`
  на каждом прогоне бесплатно запрашивает список активных видов спорта и сам
  подбирает то, что в сезоне, вместо хардкода одного турнира.

## Как это устроено

1. `odds_client.py` — `list_sports()` (бесплатно) для динамического списка
   активных видов спорта, `fetch_odds_for_sports()` — коэффициенты по каждому
   выбранному виду спорта (1 запрос = 1 вид спорта, кредитов = markets ×
   regions), `flatten_odds()` — превращает вложенный ответ в плоские записи
   с именами команд.
2. `storage.py` — кладёт каждый снимок в SQLite (`data/odds_history_v2.db`),
   плюс хранит все отправленные алерты для последующей проверки (win/loss и
   CLV).
3. `detector.py` — сравнивает новый снимок с предыдущим по каждой линии
   (контора + матч + рынок + исход) и помечает скачок, если изменение
   превышает `SPIKE_THRESHOLD_PCT` (по умолчанию 8%). Скачки на азиатских
   конторах всегда идут первыми в списке. Повторные скачки в одну сторону
   в пределах `CASCADE_WINDOW_MINUTES` помечаются как "каскад" — 🚨 SUPER ALERT.
4. `consensus.py` — считает две сводки по всему батчу разом: `sharp_vs_public`
   (средняя цена на шарп-конторах против паблик-контор) и `region_breakdown`
   (Азия против Европы) — расхождение ≥5% попадает в сводку.
5. `notifier.py` — шлёт скачки и обе сводки в Telegram HTML-разметкой:
   **название события жирным**, и в конце каждого алерта — чёткая строка
   **ИТОГ**, объясняющая, что вероятно значит движение и насколько ему
   доверять (шарп vs паблик, разовое движение vs каскад).
6. `results.py` — раз в `RESULTS_CHECK_INTERVAL_HOURS` часов (по умолчанию
   3, чтобы не жечь квоту на каждый прогон) проверяет счета завершённых
   матчей по уже отправленным алертам (`GET /v4/sports/{sport}/scores/`,
   один запрос на вид спорта, а не на матч) и считает: (а) сработал алерт
   или нет по 1X2, (б) **CLV** — используя уже сохранённую историю снимков,
   без дополнительных запросов к API: сравнивает цену на момент алерта с
   последней ценой перед стартом матча.
7. `dashboard.py` — перезаписывает `dashboard/index.html` на каждом прогоне:
   карточки "Статистика алертов" (включая средний CLV и % сигналов, где
   линия продолжила двигаться в нашу сторону), "Азия vs Европа", "Sharp vs
   public", "Recent spikes", "Latest snapshot" — везде показаны реальные
   названия команд, а не голые id.
8. `main.py` — один цикл: список видов спорта → fetch odds → detect →
   notify → save → (раз в N часов) check results/CLV → dashboard.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env
# впиши свои ключи в .env
```

Нужны два ключа:

- **THEODDSAPI_KEY** — https://the-odds-api.com/, платный тариф "20K"
  ($30/мес) уже подключён и оплачен.
- **TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID** — напиши `@BotFather` в Telegram,
  `/newbot`, получишь токен. Потом напиши что угодно своему новому боту и
  открой `https://api.telegram.org/bot<TOKEN>/getUpdates` — там будет твой
  `chat_id`.

Список отслеживаемых футбольных лиг — в `config.SOCCER_LEAGUE_KEYS`, теннис
подбирается автоматически по сезону (см. выше).

## Проверка без реального API-ключа

```bash
python test_mock.py
```

Прогоняет весь пайплайн (flatten_odds → storage → detector → consensus →
notifier → dashboard) на синтетических данных в формате The Odds API —
показывает, что логика скачков, текст алертов (жирное название события +
ИТОГ) и дашборд работают корректно.

## Квота: сколько это стоит

Тариф "20K" = 20 000 кредитов/месяц (~666/день). При текущей настройке:

- **Опрос коэффициентов** — раз в 30 минут (48 раз/день), ~9 видов спорта
  за прогон (7 футбольных лиг + ~2 турнира тенниса), `regions=eu markets=h2h`
  → 1 кредит за вид спорта → ~9 кредитов/прогон → **~432 кредита/день**
  (~13 000/мес).
- **Проверка результатов + CLV** — раз в 3 часа (8 раз/день), ~9 кредитов
  за прогон (по одному запросу `/scores/` на вид спорта с незакрытыми
  алертами) → **~72 кредита/день** (~2 200/мес).
- Список видов спорта (`/v4/sports/`) — бесплатно, не считается.

Итого ≈15 000–16 000 кредитов/мес из 20 000 — запас на рост числа турниров
и ручные прогоны. Если нужно чаще опрашивать — можно уменьшить интервал в
`.github/workflows/poll.yml`, но тогда стоит пересчитать этот бюджет.

## Как запускать постоянно

### GitHub Actions (уже настроено) — раз в 30 минут

В репозитории лежит `.github/workflows/poll.yml`:

1. Settings → Secrets and variables → Actions → добавлены `THEODDSAPI_KEY`,
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
2. Воркфлоу сам гоняется каждые 30 минут, историю коэффициентов переносит
   между запусками через `actions/cache`.

## Дальше можно добавить

- Второй провайдер специально под киберспорт (CS2/LoL/Dota2) — на The Odds
  API этого нет в принципе.
- Больше бирж/линий для сравнения sharp vs public, если добавить регионы.
- Учёт объёма движения линии (steam move detection) по нескольким конторам
  сразу, а не только по цене.
- Грейдинг результатов для спредов/тоталов, не только 1X2.
- Веб-хук вместо Telegram, если нужно завести в свой бэкенд.
